========================================
FavGallery - 建议保留的记忆类型清单
========================================


一、架构设计决策（核心）
========================================

1. 分层架构设计
    - UI Layer (UI 层)
    - Core Layer (核心业务层)
    - Data Layer (数据层)
    - API Layer (API 适配层)
    - Config Layer (配置层)

2. 本地数据存储架构
    - 作品唯一存储 + 关系表设计
    - IndexedDB 扁平化结构存储
    - 避免冗余，使用关系表关联

3. 多平台项目架构
    - 通用工具抽离决策
    - 平台适配器模式
    - 运行时切换机制

4. 文件下载混合策略
    - Blob vs ArrayBuffer 选择
    - 文件大小阈值优化


二、数据模型设计（核心）
========================================

1. 命名规范
    - 驼峰命名（禁止下划线前缀）
    - 作品 vs 视频术语区分（work ≠ video）
    - API 方法命名区分（Videos/Works）

2. 数据库表字段设计
    - 软删除字段（isDeleted）
    - count 字段设计规范
    - 分组表排序字段（sortOrder）

3. 通用关系表架构
    - relations 表设计
    - sourceType/targetType 实体关系

4. 作品数据分片策略
    - 按 createTime 季度分片
    - works_2024_Q1.json 命名规范


三、备份系统设计（核心）
========================================

1. 备份策略
    - 覆盖式备份 + 哈希对比
    - 增量检测避免重复备份
    - 季度分片存储

2. 备份触发机制
    - 列表加载：每 5 批触发一次
    - 下载进度：每 10 个作品或 1 分钟
    - 定时备份：可配置间隔

3. 数据完整性
    - 全量备份包含所有表
    - relations 表必须备份
    - 元数据记录（manifest）

4. 恢复机制
    - 后台自动执行
    - 完整性验证（哈希对比）
    - 批量恢复到数据库


四、下载系统设计（核心）
========================================

1. 五层架构设计
    - UI 层：用户交互
    - 调度层：任务管理
    - 协调层：流程控制
    - 执行层：实际下载
    - 持久层：文件保存

2. 下载任务状态管理
    - 显式状态：pending/partial/completed/failed
    - 真相来源：downloadStatus 字段
    - 断点续传支持

3. 并发控制
    - 下载锁机制
    - 串行下载（防封号）
    - 随机延迟策略

4. 批量操作状态定义
    - completed：全部成功
    - partial：部分成功
    - failed：全部失败


五、开发规范（重要）
========================================

1. 代码组织规范
    - 单一职责原则
    - 模块职责分离
    - 自底向上层层复用

2. 性能优化规范
    - 批量查询优于逐个查询
    - 避免 N+1 查询问题
    - 流式处理大批量数据

3. 状态设计原则
    - 避免冗余状态
    - 可推导的状态不存储
    - 使用计算而非存储

4. 错误处理规范
    - 完善的日志系统
    - 双日志设计（控制台 + 文件）
    - 不使用日志轮转


六、配置管理（重要）
========================================

1. 系统配置存储策略
    - settings 表存储用户配置
    - constants.js 存储系统常量
    - 配置化优先于硬编码

2. 日志路径配置化
    - 文件路径从配置读取
    - 避免硬编码路径

3. 备份批次间隔配置化
    - batchInterval 可配置
    - 时间/数量阈值可配置


七、UI 设计规范（重要）
========================================

1. 来源标签简化
    - 第一阶段只显示必要信息
    - 避免过度复杂

2. 进度显示设计
    - 使用真实总数（favoritingCount）
    - 可视化进度条
    - 实时状态更新

3. 模块化偏好
    - 清晰的代码结构
    - 合理的文件引用
    - 保持 index 文件简洁


八、沟通与协作约定（重要）
========================================

1. 开发流程偏好
    - 先讨论确认后编码
    - 纯文字沟通架构
    - 完美主义高质量实现

2. 代码输出权限控制
    - 未经确认不直接输出代码
    - 先讨论方案再实施

3. 文件全局统一性
    - 作者 ID 分类
    - 作品文件统一管理
    - 避免冗余存储


九、平台特定规范（重要）
========================================

1. 抖音平台
    - 用户信息获取优先级
    - RENDER_DATA > sec_uid > API
    - 头像画质选择（avatar_larger）

2. 跨平台兼容性
    - 避免照搬旧项目
    - 简洁优先，避免冗余
    - 平台适配器模式


十、测试与调试（重要）
========================================

1. 调试日志添加规范
    - 关键节点添加日志
    - 错误信息详细记录
    - 便于问题排查

2. 参考旧项目实现
    - NewRefactored 项目作为参考
    - 但需适配新架构
    - 避免盲目复制
